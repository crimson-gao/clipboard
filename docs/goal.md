# macOS Clipboard App 目标文档

## 1. 项目目标

开发一个仅面向 `macOS Apple Silicon` 的本地剪贴板应用。

应用常驻后台，监听系统剪贴板变化，记录历史并持久化到本地。用户可以通过快捷键或菜单栏主动唤起主界面。主界面需要能悬浮在其他应用之上，支持固定悬浮，也支持临时面板模式下点击窗口外自动关闭。

设计目标不是“功能最多”，而是：

- 结构简单
- 单一路线
- 行为可靠
- 调试直接

当前项目唯一桌面实现路线为 `Tauri 2 + React + TypeScript`。历史 Electron 路线不再保留。

## 2. 产品范围

### 2.1 必须支持

- 后台常驻运行
- 监听系统剪切板并记录历史
- 本地持久化历史记录
- 全局快捷键唤起主界面
- 主界面悬浮在其他应用之上
- 支持固定悬浮
- 支持点击窗口外自动关闭
- 支持搜索历史记录
- 支持复制历史记录
- 支持将历史记录重新写回系统剪切板
- 支持收藏历史记录

### 2.2 第一阶段不做

- iCloud 同步
- 多设备同步
- Windows / Linux 兼容
- 浏览器扩展
- OCR、翻译、AI 摘要
- 复杂账号体系
- 云端服务

## 3. 技术原则

- 保持单一桌面技术栈，不同时维护多套壳层实现
- 后端只负责系统能力、数据和窗口控制
- 前端只负责展示、交互和轻量状态
- 优先成熟方案，避免引入高风险窗口 hack
- 本地优先，数据结构先服务可靠性，再服务扩展性

## 4. 当前推荐架构

### 4.1 桌面层

- `Tauri 2`
- `tauri-plugin-global-shortcut`
- `tauri-plugin-clipboard-manager`
- `tauri-plugin-dialog`

macOS 悬浮窗口基于原生 `NSWindow` 属性配置实现，不维护第二套窗口壳层。

### 4.2 前端层

- `React + TypeScript + Vite`
- 自定义 CSS

第一阶段不引入重量级 UI 框架。组件拆分和状态边界优先于视觉库扩张。

### 4.3 持久化

当前项目使用本地 JSON 存储，目标是保持实现简单。

后续如果出现以下真实问题，再评估迁移到 SQLite：

- 记录量明显增大
- 查询 / 分页 / 搜索开始成为性能瓶颈
- 需要更强的一致性和索引能力

## 5. 模块边界

### 5.1 Rust 后端

应拆为以下职责模块：

- `window`：窗口显示、隐藏、固定、悬浮层级
- `clipboard`：监听系统剪贴板、写回剪贴板、粘贴到前一应用
- `store`：历史记录与配置持久化
- `commands`：仅暴露薄的 Tauri command 接口

禁止继续把所有逻辑堆进单个 `commands.rs`。

### 5.2 前端

应拆为以下职责模块：

- `api`：统一 invoke / event 订阅
- `hooks`：窗口焦点、分页、搜索、设置同步
- `features/clips`：列表与条目交互
- `features/settings`：设置面板

`App.tsx` 应只保留页面编排，不继续承担全部状态与副作用。

## 6. 已知风险

### 6.1 当前结构风险

- `src-tauri/src/commands.rs` 体量过大，窗口、剪贴板、存储、托盘、快捷键逻辑耦合
- `src/App.tsx` 状态过载，分页、选中、设置、焦点监听都混在一个组件里
- 部分验证期 debug 命令容易污染正式接口
- 文档与实现曾经脱节，容易导致后续继续按错误架构演进

### 6.2 重构优先级

1. 清理历史路径和无效抽象
2. 拆分 Rust 巨型模块
3. 拆分前端大组件
4. 收敛数据模型与 API 命名
5. 再考虑性能优化和数据库升级
